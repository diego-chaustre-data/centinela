Detección de fraude y lavado de activos · escrito en SQL

137.225 transacciones.
Unas pocas son fraude.

Centinela es un motor de detección escrito en SQL. Revisa todas las transacciones de un banco ficticio y señala pitufeo, cuentas mula, tarjetas clonadas y otros patrones que la norma colombiana (SARLAFT) obliga a vigilar.

No es un video ni una maqueta. Al abrir esta página se enciende un PostgreSQL real dentro de tu navegador, se crean las tablas, se generan los datos y las reglas corren en vivo. Nada sale de tu equipo.

¿Encontró lo que se escondió?

Los datos se generaron con fraude sembrado a propósito. Así se puede comprobar si cada regla encuentra sus casos y cuántas alertas levanta sobre clientes que no eran fraude.

Calibrar los umbrales

Los umbrales están en una tabla, no dentro del código. Cambia un valor y recalcula: verás cuántos casos señalaría cada regla. Bajar un umbral atrapa más fraude, pero también llena la cola de falsos positivos. Prueba a bajar perfil_veces_ingreso de 5 a 3.

Esto solo cuenta los casos que cada vista devolvería. No modifica las alertas ya creadas.

La base de datos

  • 9 tablas: clientes, cuentas, ciudades, transacciones, parámetros, reglas, alertas, bitácora y fraude sembrado.
  • Libro de solo-agregar: un disparador impide modificar o borrar transacciones, igual que en un banco.
  • Restricciones CHECK: montos positivos, transferencias siempre con contraparte, ciudad solo en canales físicos.
  • Bitácora de auditoría: cada cambio de estado de una alerta queda registrado con responsable y justificación.
  • Un reporte enviado no se deshace: la base rechaza cambiar una alerta ya reportada.
  • Detección repetible: se puede correr cada noche sin duplicar alertas.

Las reglas

  • Cada regla es una vista SQL con las mismas columnas de salida.
  • El motor recorre las reglas activas con SQL dinámico: agregar una regla es crear una vista y registrarla.
  • Técnicas: GROUP BY y HAVING, agregados con FILTER, funciones de ventana LAG(), CTE, distancia de Haversine.
  • La explicación en lenguaje sencillo la arma la propia base de datos con los datos de cada caso.

Honestidad

Todos los datos son inventados. Es un proyecto de aprendizaje de Diego Chaustre, estudiante SENA de Bases de Datos, construido con asistencia de IA. No reemplaza un sistema de monitoreo real.
